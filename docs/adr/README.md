# ADR (Architecture Decision Records)

되돌리기 어렵거나 "왜 이렇게 했지?"라는 질문이 나올 결정을 남긴다.
예: 네트워크 SDK 선택, 상태 vs RPC 구분 기준, 아바타 포맷, 송출 방식.

- 파일명: `NNNN-짧은-제목.md` (예: `0001-photon-fusion-shared-mode.md`)
- 번호는 증가만 한다. 결정을 바꾸면 기존 ADR은 지우지 않고 상태를 `대체됨 (→ NNNN)`으로 바꾸고 새 ADR을 쓴다.
- 상태: `제안` / `채택` / `대체됨` / `폐기`

## 템플릿

```markdown
# NNNN. 제목

- 상태: 제안
- 날짜: YYYY-MM-DD
- 모듈: M?

## 맥락
무엇이 문제였고, 어떤 제약(플랫폼, 맥 환경, 일정 등)이 있었나.

## 결정
무엇을 하기로 했나.

## 검토한 대안
- 대안 A: 왜 안 골랐나
- 대안 B: 왜 안 골랐나

## 결과
좋아지는 점, 감수하는 점, 나중에 다시 볼 조건.
```
